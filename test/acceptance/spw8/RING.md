# RING — リング 64 MiB が PS の 0.3 s の止まりを吸う

- **前提**: V2-b と同じ（tint 20.48 ms・32 窓）。2G-4 の RING と同じ仕掛け（specd の `--posctl-ring-stall` を 0.3 s に）
- **手順**: specd を 0.3 s の止まりを入れる形で起こし、60 s 受ける
- **合格**: pl_drop 0・受けの kgap 0・説明のない欠け 0。pl_peak ≦ 64 MiB の 1/2（PL は PS へ ≒ 51 MB/s、0.3 s で ≒ 15 MB）
- **陽性対照**: 止まりを 8 s にすると pl_drop > 0（V2-b の陽性対照）
- **記録**: なし（2G-4 で入れた判定）
- **記録（M6）**: YATSUGATAKE M6（2026-11-04、M5c の bit、specd `--posctl-ring-stall 0.3`、60 s、`runs/m6/ring`・`ring2`・`ring3`）。**1 回目**（07:31 UTC）: 0.3 s の止まり（周 99、538 ms）の後、周 156 の前に周の計りの外で ≒ 0.5 s 止まり（その周 589 ms・溜まり 40 倍）、**pl_drop 334・kgap 32・pl_peak 64 MiB**、照合は失敗（kgap > 0）・説明のない欠け 0。**不合格**。止まりの原因を見るため、GC の時間を書き出す試験用の場所（`acqboot.py` に gc.callbacks、製品には入れない）で 90 s（止まりなし）を回した: 20 ms を越える GC は起動の途中の 4 回（122〜229 ms）だけで RUN の中には無く、その回しには大きな止まりも出なかった（原因は分かっていない）。同じ場所で同じ条件を 2 回回し直した: **2 回目・3 回目とも pl_drop 0・kgap 0・照合 通過・pl_peak 27.5 MB / 28.1 MB（線 32 MiB = 33.6 MB）**、周の最長は止まりの直後の 525・527 ms だけ。**3 回のうち 1 回が不合格**。止まりだけで PEAK が 28 MB まで上がる（取得の CPU ≒ 70 % で追いつく速さが ≒ 0.3 倍しかない）ので、線までの余裕は ≒ 6 MB。陽性対照（8 s）は V2-b の記録
- **記録（M6 の回し直し）**: YATSUGATAKE M6 の回し直し（2026-11-04、M5c の bit のまま。ソフトは commit 808f398 の `sw/pynq/`（できた束を C が出口の溜まりへ直に SPEC の記録として書く）をボードの `~/spw8-m6b` に写し sha256 で同じ。specd `--prefault --fast --fast-ring --loop-log-ms 0.1`、`runs/m6b/`）。`--posctl-ring-stall 0.3`・60 s を 3 回、回ごとに specd を起こし直した（12:15・12:16・12:18 UTC、`runs/m6b/ring1`〜`ring3`）。3 回とも **pl_drop 0・受けの kgap 0・説明のない欠け 0・照合 通過**・miss 0。**pl_peak 21.2 / 21.2 / 21.2 MB**（線 33.6 MB、1 回目の 27.5〜28.1 MB より下がった）・周の最長 423・409・410 ms（0.3 s の止まりの周）・loop_slow 4・3・3（どれも最初の 1 分）。取得の CPU（`spw_c_*` の和 ÷ RUN 60.8 s）≒ 33.6 %。1 回目に出た止まりの重なりは出なかった（原因は分かっていないまま）。陽性対照（8 s）は V2-b の回し直しの記録。**3 回とも通過**
