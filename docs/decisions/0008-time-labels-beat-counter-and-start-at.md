# 0008. 時刻は 256 MHz のビートと 1PPS のスタンプで貼り、開始は予約したビートで

- 状態: 採用
- 決定日: 2026-09-17（予約時刻での発火）・2026-10-02（256 MHz の 64 bit のビートに置き直し）
- 根拠: study-rfsoc proj007・proj016・INTERFACE.md の 1.

## 背景

ダンプに絶対時刻を貼り、複数のコア（4 ADC の窓・全帯域・TP）を同時に開始したい。1PPS は観測所から来る。

## 決定

- **時刻の物差しは 256 MHz の 64 bit のビートカウンタ T**（DSP のクロックの数。入力の valid の数ではない）。1 秒 = 256,000,000 ビート
- **1PPS は毎秒のトリガにしない。** PPS の立ち上がりのビートをスタンプとして取り、2 発目以降は残差の監視に使う
- **開始は予約したビート（START_AT）で行う。** ARM しておいた全コアが同じクロックに RUN を受ける（RUN_T = START_AT + 1）
- 各ダンプに、最初のフレームが入ったビート（DUMP_T）を貼る。UTC への換算は PS の timebase が行う
- ダンプの区切りは秒に揃えず、毎回同じ N フレームにする
- 1PPS の両系統（TRIG・COMP）を取り込み、グリッチを独立に数える

## 理由

- fs が整数（1 秒 = 整数ビート）なので、一度原点を決めれば以後は数えるだけで PPS と整合する。PPS の立ち上がりを直接開始に使うと、ケーブル長とコンパレータの遅れが毎回時刻に乗り、較正できる定数にならない
- PPS が欠けても止まらない。1 秒以外の積分時間でも破綻しない
- 実測: 120 秒で PPS の間隔の残差 0 ビート。10 MHz を水晶に替える対照で −111 ppb を検出でき、測定が本物と言えた
- 1 秒が整数個のフレームになるのは 128 MHz 以上の幅だけなので、秒に揃えると狭い窓でダンプの長さが揺れる

## 見送った案

- **PPS の立ち上がりを直接 arm に配る**: 上のとおり、時刻に毎回ずれが乗る
- **ダンプの区切りを秒の格子に揃える**: 2 MHz・100 ms で長さが最大 2 % 揺れる

- 時刻の格子と積分時間は [0009](0009-time-grid-and-integration-time.md)
- 健全性の語に PPS の欠落・間隔・グリッチ・原点の変化を出す（[0014](0014-config-capture-and-health-word.md)）
- ADC ごとのコアまでの遅れ（adc_to_core）は Overlay ごとに閉ループで測る（判定 F-2）
