# 0023. 時刻の較正はボードごとに設置の後で測り、ボードにだけ置く（bit ごとには測らない）

- 状態: 採用
- 決定日: 2026-10-29
- 根拠: YATSUGATAKE の F-2（SAM45-Fine 2026-10-21・SAM45-Wide M6 2026-10-26）、study-rfsoc proj021・proj023・proj026

## 背景

時刻の較正（`timebase.CAL` の `adc_to_core_ns`）は bit の (BIT_KIND, BIT_REV) を鍵にし、bit ごとに F-2 を測って足す決まりだった（CAL に無い bit は「未較正」で止まる）。
F-2 は 1PPS を ADC_A〜D にも入れる配線 P が要り、ケーブルを入れ替えて 2 回測る。性能評価の途中で配線を替えることになり、評価の律速になっていた。残りの 7 本の bit でも同じことが続く。

分かっていたこと:

- SAM45-Fine（2, 3）と SAM45-Wide（1, 1）の `adc_to_core_ns` の差は ≦ 1.6 ns。どちらも共通コアの RFDC の設定とギアボックスを通る。2G-4（proj031 R-5）の M = 69.4〜70.4 ns も Wide の M（69.9〜71.5 ns）と ≦ 1.6 ns
- Overlay を載せ直すたびに 4 ADC がそろって ≒ 0.9〜1.18 ビート（≒ 3.5〜4.6 ns）動く（原因は未確認）。1 回の F-2 の確かさはこれで決まり、bit の差より大きい
- M6 のケーブルの入れ替えで、ADC ごとの残りは −0.14〜+0.10 ビート
- 要求は 100 µs（[0007](0007-no-mts-no-pps-into-adc.md)）。定数はどれもそれより 4 桁以上小さい
- 本番の時刻に効くのは、ボードの個体と設置（1PPS の入口の LPF・ケーブル）。開発のボードで測った値はその代わりにならない

## 決定

- **bit ごとの F-2 はやめる。** ADC → コアの道（RFDC の設定・ギアボックス）が同じ bit は、同じ値を使う。道を変えた bit だけ `timebase.ADC_PATH` に新しい番号で足し、別に測る
- **本番のボードは、設置の後にユーザーが `sw/pynq/timecal.py` で測り、較正ファイル（`time_cal.json`）を自動で作る。** 以後はそのファイルで動く
  - 測るのは形 (a) の M = adc_to_core − pps_det だけ（LPF の有り無しの測り分けはしない。時刻の式に効くのは M だけ）
  - Overlay を載せ直して 5 回測った平均。ばらつきを `bound_ns` に入れる。ケーブルの入れ替えはしない（分配器から ADC まで同じ長さのケーブルを使う）
  - 鍵はボードの印（eFuse の DNA、読めなければ eth0 の MAC）。別のボードでは当たらない（→ [ADR 0026](0026-board-id-mac.md)）
- **較正ファイルはリポジトリに戻さない。** ボードの `/etc/yatsugatake/time_cal.json`（環境変数 `YATSUGATAKE_TIME_CAL` で替えられる）にだけ置き、ユーザーの手元で持つ
- **較正ファイルが無い・当たらないときは、`timebase.CAL` の開発の値（SAM45-Fine・Wide の F-2、無い bit には Wide の値）を「暫定」として当てる。** 止めない代わりに、specd の `ID` の `tcal`（`board` / `provisional`）・`GET CAL`・START の EVENT の `time_cal` に印を出す

## 理由

- bit の差（≦ 1.6 ns）は 1 回の測りの確かさ（Overlay ごとの ≒ 4.6 ns）より小さく、bit ごとに測っても確かさは上がらない
- 本番の時刻を決めるのはボードと設置なので、そこで測るのが筋。開発の評価から配線 P が消える
- 個体の値は公開のリポジトリに置くものではない。ボードの印・測った日・ばらつきはファイルに残るので、ボードの上で辿れる
- 暫定でも誤差は数 ns で要求の 100 µs に届かない。止めるより、印を付けて動かすほうが開発の役に立つ。印があるので、本番のデータが暫定の較正で取られたことは後から分かる

## 見送った案

- **bit ごとに F-2 を続ける**: 上の理由で、配線の替えに見合う確かさが得られない
- **個体の値もリポジトリの CAL に足す**: 公開のリポジトリに個体の値を置くことになり、ボードの交換や設置の変更のたびに PR が要る
- **較正ファイルが無ければ止める**（今までの「未較正」）: 開発中の bit が全部止まる。暫定の印で足りる

## 影響

- `timebase.Timebase` は較正ファイルを読み、ボードの印と ADC → コアの道を照らす（`select_cal`）。CAL に無い bit でも止まらない
- **ADC → コアの道（RFDC の設定・ギアボックス）を変える RTL は、`ADC_PATH` に新しい番号を足す**（足し忘れると、その bit に古い道の較正が当たる。差は数 ns の見込み）
- 測り直すのは: ボードの交換、1PPS の入口の LPF・ケーブル・分配の変更、`ADC_PATH` の番号が変わったとき
- 判定の F-2 は、開発のボードで ADC → コアの道を変えた bit を確かめるときだけ回す
- `tp_cal.json`（TP の dBm、個体の値）はまだリポジトリにある。同じ扱いにするかは別に決める（→ [0025](0025-tp-calibration-per-board.md)）
- 2G の PS（`sw/pynq-2g/`）は M5 で `sw/pynq/` に一本化するまで、今までの CAL の形のまま。一本化のときにこの形に合わせる
- 見直す条件: Overlay ごとの共通のずれの原因が分かり、1 回の測りの確かさが bit の差より良くなったとき
