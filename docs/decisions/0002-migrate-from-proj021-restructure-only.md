# 0002. 移植は proj021 を土台にし、構成替えだけを行う

- 状態: 採用
- 決定日: 2026-10-08
- 根拠: study-rfsoc proj020・proj021・INTERFACE.md の 9.（移植）

## 背景

study-rfsoc には完成した SAM45-Fine が 2 つある。proj020（PFB T = 4、インターフェース v1）と、開発中の proj021（同じ分光を、インターフェース v2 の上で）。どちらを製品の出発点にするかを決める必要があった。

## 決定

- **移植の土台は proj021 の最後の形にする。** proj020 からは移さない
- proj021 は study-rfsoc で、いつもどおり自己完結に作る
- **製品リポジトリへの移植では構成替えだけを行う。** 機能・ID・係数を同時に変えない
- 移植の合否は「proj021 と同じものができること」（詳しくは [`../migration.md`](../migration.md)）
- proj021 の中で、ソースを `src/common/`・`src/sam45fine/`・`src/board/` に分けておく（移植をほぼ機械的にするため。proj021 の自己完結は保つ）

## 理由

- **proj020 はインターフェース v1**（AXI4-Lite で全部読む・4096 ch 固定・s45proto v1）で、v2 での置き換えが決まっている（[0016](0016-interface-v2.md)）。proj020 を出発点にすると、最初の版が「すぐ捨てる約束」になる。公開後に利用者が v1 に合わせて作ると互換性の問題が残る
- **共通コアの境界は v2 で決まる**（流れと自己記述・PL が書くリング・レコードと CRC・specd の束ね）。v1 の境界で分けると、v2 で分け直すことになる
- proj021 は測ることが多く（1 GbE の実効・CMA・HP0 か HPC0 か・A53 の処理量）結果が読めない。性格は試行なので、study-rfsoc に置く（[0001](0001-separate-trial-and-product-repositories.md)）
- **変更は一度に一つ。** v2 への作り替えと構成替えを同時に行うと、ずれたときに原因を切り分けられない

## 見送った案

- **proj020 から移植する**: 上のとおり、v1 を出すことになる
- **proj021 を製品リポジトリで直接作る**: 作り替えと構成替えが同時に起きる。製品の履歴の最初が試行錯誤で埋まる

## 影響

- 製品リポジトリの最初のリリースは proj021 の完成後になる
- 例外: v1 の SAM45-Fine を先に誰かへ渡す必要が出たら、study-rfsoc のタグで出し、製品の系譜には入れない
