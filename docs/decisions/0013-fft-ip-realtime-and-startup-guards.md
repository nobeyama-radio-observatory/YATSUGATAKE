# 0013. FFT IP は realtime・資源優先。起動の途切れは多段で守る

- 状態: 採用
- 決定日: 2026-09-28
- 根拠: study-rfsoc proj011・proj012

## 背景

全帯域の分光（8192 点 = 16 レーン × 512 点）で、FFT IP が DSP の大半（1ch で 944 のうち 800、4ch で 88 %）を使い、`-1` の余裕も 2 % しかなかった。

## 決定

- **FFT IP を realtime・資源優先（乗算 3 回・LUT のバタフライ）にする**
- realtime の IP は入力の途切れを待たずに進むので、**起動の直後の途切れを多段で守る**
  1. 起動の見張り: 入力が 64 µs 途切れずに続くまで入力の口を開けない
  2. ギアボックスのしきい値 K（既定 2）: FIFO に K 語溜まるまで読み出しを止める
  3. FLAGS: 口が開いた後の途切れを検出して立てる
  4. 記録の自動のやり直し（PS）

## 理由

- DSP 944 → 480（4ch で 45 %）。減らしたのは乗算器とバタフライの設定で、realtime ではない。realtime はタイミングのため（nonrealtime の CE の大きなファンアウトが消える）
- realtime の代償として、起動の直後の入力の途切れで IP の数えがずれる事象（TLAST 事象）が出た。データの枠はずれない
- 途切れを「早い型」（見張りが吸収）と「遅い型」（Overlay の起動だけ、見張りの外）に分け、**K = 2 で Overlay の途切れが 27/80 → 0/80** になった

## 見送った案

- **nonrealtime の IP**: DSP とタイミングの両方で窓の切り出しの予算を塞ぐ
- **見立て「gray の到着の差で余裕 0 の読み出しが空振りする」を直す**: 遅いビットの検証ビルドで棄却された

## 影響

- **遅い型の途切れの正体は未解明**。守りで吸えているが、原因は持ち越し
- 見張りには陽性対照（注入: INJ）を置き、見張りが効くことを実機で確かめる（[`../knowledge/verification.md`](../knowledge/verification.md)）
