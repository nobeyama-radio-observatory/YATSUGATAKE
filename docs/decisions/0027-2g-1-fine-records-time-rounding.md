# 0027. 2G-1-Fine の流れは KIND 5 STAGE2・荒い ch ごとのレコード、ブロックの位相は T に固定、荒い段の丸めは変えない

- 状態: 採用
- 決定日: 2026-10-30
- 根拠: study-rfsoc proj037（R-1・S-1・T-1〜T-4）・proj028（F-8）・[ADR 0022](0022-2g-1-fast-and-fine.md) の「移すまでに決める」3 つ

## 背景

ADR 0022 は 2G-1-Fine（BIT_KIND 12）を移すまでに、1PPS・DUMP_T を載せること、流れの形（レコードを荒い ch ごとに分ける案）、荒い段の丸めの線（f ± k·fs/56）を下げるかを決めるとした。
2G-1-Fine の 1 ダンプ（286.72 ms）は 3,670,016 ch × 8 B = 29.4 MB で、CMA の 64 MiB に 2 つしか入らない。細かい側は荒い ch（64 ch、使うのは 32）を 1 本ずつ積み終える。
ch → IF は f = G·fs / (56·N_f) で、2^n 点の FFT ではない。荒いブロックは 56 サンプル = 3.5 ビートで、G（2^19 ビート）とは 7G ごとにしか揃わない。

## 決定

- **流れの KIND に 5 STAGE2（2 段）を足す。** NCH 3,670,016、PARAM[7:0] = log2 N_f（17）。ch i の周波数は (S0 + i)·fs / (56·2^PARAM[7:0])
- **レコードは荒い ch 1 本 × 1 チャンク**（中身 114,688 × u64 = 917,504 B）。1 ダンプ = 32 レコード。
  SEQ はレコードごとに +1、DUMP_K はチャンクの番号、語 7 の上位は S0 = k·114,688、DUMP_SAT は荒い ch k の 8 bit の飽和の数、DUMP_N は積んだ細かいフレームの数（ふつう 160）
- **RUN の最初のダンプ**（細かい PFB の履歴が無く DUMP_N 157）は PL がそのまま出し、PS は束ねの規則（5.1 の 4.）で捨てる
- **荒いブロックの対（7 ビート）の頭を T の 7 の倍数に固定する。** START_AT は T の tint の倍数（BASE = 140 G = 20·7G の倍数）なのでいつもブロックの頭になり、DUMP_T = RUN_T ＋ DUMP_K·BASE_BEATS が式で決まる。実際のスタンプと式の食い違いは粘着の FLAGS で見張る
- **D_eff（STAGE2）= 1.5·N_f·56 ＋ 836 サンプル ＋ D_S**。N_f 131072 で 688,180.25 ビート（2.688204 ms）＋ D_S。D_S は RTL の sim で出す
- **荒い段の丸め（SH 18・z 18 bit・8 bit）は変えない。ディザも入れない。** 係数の像（f ± k·fs/56、CW に比例）は既知の性質として bits.md に書く

## 理由

- **レコードの単位**: 細かい側の出方そのままで溜めが要らない。1 回の量が 2G-1-Fast（1 MiB）と同じで、PS の読み（102 MB/s）も同じ
- **KIND を分ける**: ch → IF の式が FULL（i·fs/N）とも SLICE とも違う。式の違う作りは KIND で分けるのが 2.1 の約束
- **SEQ をレコードごとに**: リングと PS の「SEQ の飛び = 欠け」の見張りが KIND に依らず今のまま使える。ダンプの束は DUMP_K（と DUMP_T）で集める
- **最初のダンプを PS が捨てる**: 束ねの今の規則（DUMP_N がどれも BASE / L）がそのまま捨てる。失うのは RUN ごとに 1 ダンプ（0.29 s）
- **ブロックの位相**: proj028 の荒い段は位相を「入力の valid が初めて立った拍」から数えるので、ブロックの格子と T の関係が Overlay ごとに違う。T に固定すれば DUMP_T に遅れの定数が要らない
- **D_eff**: 細かい PFB（T 4、対称）の重心は矩形のフレームより 1.5·N_f ブロック前、荒い PFB（1728 タップ、対称）はブロックの覆うサンプルの中心より 836 サンプル前。
  係数の 2 乗の重みを直に足した模型（N_f 256・1024）で差 ≦ 3e-11 サンプル、陽性対照（対称でない窓）は外れた
- **丸め**: F-8 の線（−65〜−80 dBc）は雑音源を切った試験（ADC の雑音 σ 5 LSB）だけのもの。運転の入力（σ ≒ 1031 LSB、−18 dBFS）では、bit 単位の模型の丸めの誤差に線は無く（CNR +2〜+50 dB、雑音の −54 dB より下）、
  1 時間の積分の揺れ（−31.5 dB）より十分低い。残る係数の像（k = ±1 で −69〜−86 dBc、|k| ≥ 2 で −84 dBc 以下）は丸めを直しても変わらず、ADC の交互の誤差の線（−55 dBc 級）より低い

## 見送った案

- 1 ダンプを 1 レコード（29.4 MB）: CMA に 2 つしか入らない
- SEQ をダンプごと（32 レコードで同じ）にし、k を語 7 で見分ける: リングと PS の欠けの見張りが KIND ごとに変わる
- RUN の 3 フレーム前から corner turn を書き始めて最初のダンプも 160 フレームにする: DUMP_T が G の格子から 2.625 G ずれる
- PL がチャンク 0 を出さない: SEQ・DUMP_K が 1 から始まり、帳簿の約束が KIND で変わる
- 荒い段の SH を下げる・語長を広げる・ディザ: 運転の入力では効く線が無い。SH を下げると z の飽和が ADC より先に来る

## 影響

- 2G-1-Fine の RTL（ヘッダ・ブロックの位相・チャンクごとの帳簿）は移植のときに作る（共通部の一本化（PR #74）の後の `hw/common/` の上で）
- specd は STAGE2 の束ね（ダンプ m = 32 本）と ch → IF の式を持つ
- 雑音源を切って CW を測る試験では、f ± k·fs/56 に −65〜−80 dBc の丸めの線が見える。判定に使う線の高さは雑音源 ON か模型と並べて読む
