# 0004. 速度グレード `-1` でビルドし、PS のプリセットを明示して当てる

- 状態: 採用
- 決定日: 2026-09-28（`-1` で閉じることを合否に）・2026-10-01（実機の .bit も `-1` でビルド）
- 根拠: study-rfsoc VERSIONS.md（Part の未確認事項）・proj013・proj015

## 背景

ボードの速度グレードについて資料が食い違う。board file は `xczu48dr-ffvg1517-2-e`（`-2`）を宣言し、リファレンスマニュアルの本文には `-1` と読める記載がある。JTAG の IDCODE には速度グレードが入っておらず、判別できない。決着はチップ上面の刻印だが、ヒートシンクを外す必要がある。

## 決定

- **速度グレード `-1` で閉じることを合否の条件にする**（`-1` で閉じる設計は `-2` でも必ず閉じる）
- **実機に載せる .bit も `-1` でビルドする**
- `-1` のビルドは board_part を使えないので、ボードのプリセットが PS に当てる設定を `ps_preset.tcl`（生成物だがリポジトリに入れる）から明示して当て、読み返して照らす

## 理由

- 遅いほうで解析して閉じれば、どちらのグレードであっても安全と言える。刻印を読まずに済む
- **`-2` のビルドの配置配線は `-1` の遅延で閉じている保証が無い。** 同じ RTL で `-2` +0.007 ns・`-1` −0.767 ns になった例がある（proj015 rev1）。`-2` で作った .bit を載せると、実機が `-1` だった場合に閉じていない回路を動かすことになる
- board_part のまま part を差し替えると、board_part が part を `-2` に**黙って戻す**（WARNING 1 行だけ）。プリセット適用後に board_part を外すと BD の IP が locked になる。`set_speed_grade` は 2024.1 で機能しない。3 つとも試して塞がった

## 見送った案

- **`-2` でビルドし、`-1` は検証だけに使う**（proj014 までの運用）: 上の proj015 rev1 の例のとおり、実機の .bit が `-1` で閉じている保証にならない
- **刻印を読む**: ヒートシンクを外す必要がある。`-1` で閉じない設計が出て初めて必要になる

## 影響

- `-1` の余裕は小さい（SAM45-Fine で +0.047 ns、実装の戦略 Performance_Explore を使って）。資源を足す変更では最悪経路を先に見る
- ビルドの前に part が要求値どおりかを `build.tcl` で照合し、違えば止める（[`../knowledge/verification.md`](../knowledge/verification.md)）
