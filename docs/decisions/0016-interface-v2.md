# 0016. インターフェース v2（流れと自己記述・PL が書くリング・float32・束ね・LOAD）

- 状態: 採用（番地の細部は proj021 で確定）
- 決定日: 2026-10-08
- 根拠: study-rfsoc INTERFACE.md（v2）・proj020・proj021

## 背景

proj020 までの読み出し（AXI4-Lite で 4096 語を全部読む・スペクトル領域は 4096 ch・窓は 1 ADC に 4 つまで）は SAM45-Fine では足りたが、9 本の bit には足りない。

- AXI4-Lite の実効は ≒ 9〜15 MB/s。Fine より上の bit は 25〜205 MB/s を読む必要がある
- スペクトル領域に 32768〜131072 点が入らない。SpW6・8・20 の窓の数が入らない
- 1 GbE を 64 bit の生の値で越える構成がある

## 決定

制御の約束（時刻・格子・設定の取り込み・帳簿・健全性・単位）は**変えずに固定**し、次を足す。

- **流れ（stream）**: 全帯域・窓・全帯域の切り出しを同じ枠で扱い、違いは KIND（FULL・SLICE・DDC）だけにする。**自己記述のレジスタ**（IF_ID・CORE_PORT など）で、bit が自分を説明する。PS は .hwh の IP の名前でコアを見つける
- **データの道は PL が書き手になる DDR のリング 1 本**（DataMover ＋ 自作の司令）。空きが無ければ丸ごと捨てて DROP_CNT を数える。レコードの尾に SEQ の写しと CRC-32
- **値の形**: リングの中は u64 の生、ネットワークはいつも float32。float32 でも予算に入らない構成はネットワークの tint の最小を延ばす
- **PL のダンプは 10.24 ms を基本の単位**にし、長い積分は specd が束ねる（整数の和なので PL で積分した値と bit 単位で同じ）
- TP もレコードにする。SNAP は頼んだときだけ
- 受け側へ送る utc_ns は実効の区間の始まり（PFB の重心のずれも PS が引く）。遅れの定数は (BIT_KIND, BIT_REV) ごとの表
- **specd に LOAD bit=<名前>** を持たせ、読み込める bit はボードの `bits.json` にあるものに限る
- s45proto v2（float32・nch・df・n_sum を頭に）

## 理由

- 点数・窓の数・dt が bit ごとに変わっても、**PS と受け側のソフトを 1 本にする**。dt を bit の性質から外す
- 溢れを PL で数えられるのは PL が書くリングの形だけ
- PL → DDR は詰まらないので、PL で値を切る理由が無い。float32 の丸め（≦ 6e-8）はラジオメータの雑音より 3 桁以上小さい

## 見送った案

- **AXI DMA を 1 件ずつ**: 256M で PL に 10 MB の溜めが要る
- **AXI DMA の SG の環**: 溢れると読んでいる最中に上書きされる
- **コアごとにリング 1 本**: DataMover と司令がコアの数だけ要る
- **PL で 32 bit に丸める**: 束ねが bit 単位で一致しなくなる
- **クライアントで束ねる**: 10.24 ms のまま送ると 1 GbE を超える構成がある
- **目録のレジスタ**: PYNQ は既に .hwh を読んでいる
