# 0028. WRST_T の下限は bit ごと、SpW の窓のキーは論理の窓

- 状態: 採用
- 決定日: 2026-11-03
- 根拠: study-rfsoc proj032（P-9 の rev 10・P-10b・P-13b、README の「決めた（2026-11-03）」）・[`migration-spw8.md`](../migration-spw8.md)

## 背景

SpW8（BIT_KIND 7）の RTL は、移す前に 2 つの点で今の仕様から外れていた。

1. **WRST_T**: SAM45-Fine の窓（`hw/common/win_core.v`）は WRST のリセットの長さを WRST_T クロック（0 は 1）とする。
   SpW8 の rev 10 は、WRST で替わる窓の設定を受け手（前段・機関・受け手）ごとに 2 段の写しで配る。写しがリセットの中で揃うように、**WRST_T が 8 未満なら 8 クロックにする**（`spw_regs.v`）。
   既定は 64 で、PS は WRST_T を書かない。外れるのは WRST_T 1〜7 の振る舞いだけ
2. **窓のキー**: interface 5. の SET のキーは「ADC のラベル＋流れの番号 s」（`A0` = ADC_A の s = 0）。
   SpW の流れ s は、粗い PFB の偶奇（PSPLIT）の組・時分割の機関（lane）・履歴の枠に結び付いていて、利用者の窓（IF・幅）の並びから計画（spwplan、proj032 P-10b）で割り当てる。
   利用者に s を選ばせると、偶奇・lane の和・枠の約束（PL の WRST の約束 [1]〜[6]）を利用者が背負う

## 決定

- **WRST_T の下限は bit ごと。** WRST_T（DDC の 0x11C、[15:0]、既定 64）は、bit ごとの下限より短い値を下限に切り上げる。SAM45-Fine は 1（0 は 1）、**SpW8 は 8 クロック**。下限は bit の約束として spec（interface 2.5）に書く
- **SpW の窓のキーは論理の窓。** `A0`〜`A7` は利用者の並び（ADC_A の窓 0〜7）で、流れの番号 s ではない
  - specd は計画で論理の窓を流れ s に割り当て、対応（キー ↔ s）を持って STATUS に出す
  - **受け側へのレコードも論理の窓の番号**で出す（specd が s から読み替える）
  - SET は 1 コアの窓の組をまとめて受け、**計画できなければ組ごと断る**（効いている組は変わらない）
  - 粗い ch（2 番目に近い ch を使うか）・機関・枠は計画の既定で決め、利用者には出さない。試験のために決め打つ口だけ残す
  - PSPLIT の無い bit（SAM45-Fine など）では割り当てが恒等で、今の振る舞いと同じ

## 理由

- **WRST_T**: 写しの 2 段は rev 10 でタイミングを閉じるために入れたもの（proj032 P-9、WNS −0.212 → −0.024 ns、戦略を替えて +0.016 ns）。既定の 64 と PS の使い方では振る舞いが変わらないので、実害のない形で仕様と実装を合わせる
- **論理の窓**: 1 本ずつ窓を入れ替えると、途中で偶奇・lane の約束が崩れる（R-1 の「WRST はコアで 1 つ」と同じ理由で、組で受ける）。
  受け側が論理の窓の番号で受ければ、利用者の並びがそのまま記録に残り、計画の版が変わっても受け側の読み方は変わらない

## 見送った案

- WRST_T の下限を全 bit 共通の 8 にする: SAM45-Fine の RTL（0 は 1）が仕様から外れる（SAM45-Wide・2G は WRST_T を持たない）
- WRST_T の下限を仕様に書かない: WRST_T 1〜7 の食い違いが残る
- 今のまま `A0` = s: 利用者が偶奇・lane の和を背負い、1 本ずつの入れ替えで途中に約束が崩れる
- 論理の窓で受け、受け側には s で出す（受け側が STATUS で読み替える）: 受け側が計画の対応を持たないと記録が読めない

## 影響

- interface 2.5（WRST_T の下限）・5.（SpW の窓のキー）・6.（SPEC の s の欄は論理の窓の番号）と bits.md の SpW8 の行を直す
- specd の SpW Backend（移植の M5b）が計画（spwplan）・組ごとの SET・対応の STATUS・レコードの読み替えを持つ
- 窓の遅れ D(NS) を (BIT_KIND, BIT_REV) の表に移すこと（interface 5.2 の決定）は移植の M5a で、`timing.md` の残りと一緒に片付ける
