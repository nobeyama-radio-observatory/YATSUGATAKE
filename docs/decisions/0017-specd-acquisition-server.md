# 0017. データ取得サーバー specd の形（行単位の命令・2 プロセス・ACK まで保持）

- 状態: 採用（「送るのは生の 64 bit だけ」は [0016](0016-interface-v2.md) で置き換え）
- 決定日: 2026-10-05
- 根拠: study-rfsoc proj018

## 背景

ボードの PS で取得し、制御 PC の命令で動き、ダウンロード PC へ記録を送るサーバーが要る。

## 決定

- **制御は行単位のテキスト**（ASCII・LF 区切り・1 命令に 1 行の応答）。SET・START・STOP・SEND・STATUS など
- **取得と通信を 2 プロセスに分け、間は共有メモリの溜まり**（境目は言語に依らない形: バイトの環と固定の頭）
- 記録には頭に CRC-32 と通し番号を付ける。**受け側の ACK まで溜まりに残す**
- 溜まりが溢れたら捨てて、捨てた範囲を DROP で言う
- 言語は Python。取得の 1 周の最大が基準（SAM45-Fine で 38 ms）を超えたら、取得の側だけを C に替える

## 理由

- 行単位のテキストは人が nc で試せ、検証が簡単
- 取得と通信を分ければ、受け側の止まりが取得を止めない
- 最初の版は sendall の後に消していて、受け側を切ると記録が黙って消えた。ACK まで残す形に直した
- 実機で 1 時間・87,890 ダンプ × 8 窓・TP 4 本を読み落とし 0・欠け 0・CRC の不一致 0。取得の 1 周の最大 29.13 ms（基準 38 ms 未満）

## 見送った案

- **最初から C で書く**: PL の起動（Overlay・xrfdc・クロック）と timebase は実機で通った Python の資産がある

## 影響
