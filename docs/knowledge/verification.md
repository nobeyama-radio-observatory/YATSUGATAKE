# 検証の規約 — 「動いているように見える失敗」に備える

この開発で踏んだ穴は、ほぼすべて**ビルドが通り、実機も動き、症状が出ない**形をしていた。目視では出ないので、機械に見張らせる。

## ビルド

- **合成の前に part の一致を検証する。** board_part による part のすり替えは WARNING 1 行でしか知らされない。要求値と実際値を突き合わせ、違えば `exit 1`（study-rfsoc VERSIONS.md）
- **`build.tcl` に結線の照合を常設する。** リセットやクロックの取り違えは、ビルドも実機も通り、時刻の原点の番号が嘘をつくだけで済んでしまう。ブロックデザインのネットを読み返して駆動元を照合し、違えば `exit 1`（proj007 rev2・proj012）
- **照合は「在るか」と「在ってはいけないか」の両側を持つ。** 片側だけの照合は、読む範囲を間違えていても通る。IP のトップの VHDL を component 宣言ごと読んでいて、「在るか」は通り続け、「在ってはいけない」を足した瞬間に落ちた例がある（proj011）
- **XDC には制約だけを書く。** `if` / `foreach` は CRITICAL WARNING で弾かれ、**その行は実行されない**。防御的に書くと防御自体が動かず、制約が丸ごと無効になる。条件分岐と検証は `build.tcl` の `open_run` の後で行う（proj003。WNS −4.556 ns のビットストリームが完走した）
- **`launch_runs` の警告は `make` のコンソールに出ない。** `runs/*/runme.log` から CRITICAL WARNING を拾い上げる
- **`make` の成功を信用しない。** ターゲット名の衝突で `up to date` と言って正常終了した例がある（proj007）
- **タイミングが閉じていないビルドは `make` を失敗させる。** 使ってはいけない .bit を黙って置いていくと、後で必ず取り違える（proj003）
- **一番きつい経路のクロック対を、WNS が正でも必ず出す。** 宣言し忘れた乗り換えが、たまたま間に合っていただけかもしれない（proj006）
- **CDC は `report_cdc` を正とし、Critical は件数で読まない。** 分類の移動で直ったことを確かめる。「Critical 0」を見張りとして保つ（proj006・proj012）
- **ビルドの後、今の RTL が焼けたかを確かめる。** ビルドの指紋（BUILD_TAG など）をログと実機の ID で照らす

## sim

- **RTL を変えたら sim を回す。** 自作部分を模型と bit 単位で照合できるのはここだけ（実機の判定は振幅の近さしか見ない）
- **見張りには陽性対照を用意する。** 立ったことのないフラグは「異常が無い」と「見張りが壊れている」を区別しない。sim に、わざと異常を起こす変種（例: 検査の数えだけをずらす）を置き、立つべきときに立つことを確かめる
- 変種は同時に回し、成否は make の終了状態ではなく、各ログの「全部通過」で判定する

## 実機

- **PS のスクリプトは、載っている .bit の ID（版・変種）を読んで照合してから動く。** スクリプトだけ新しく .bit が古い、という食い違いをここで止める
- **粘着するフラグは、消す前に読む。** 見張りの道具が区間の頭で黙って消していて、事象の起きた区間を見落とした例がある
- **同じ名前のファイルを持つディレクトリを増やさない。** 別の作業ツリーで走った `make` の「完了」を本来のビルドと取り違えた例がある。ボードへ送るときは glob で複数の build ディレクトリを指さない（同じ名前に上書きされ、最後に残ったものが載る）

## 再現性

- **同じ RTL の作り直しは WNS まで再現する。** ビルドに時刻などの変わる定数を入れない（入れると配置が組み替わり、再現しなくなる）。版を .bit に焼き込むときも配置に触れない方法を選ぶ（[ADR 0018](../decisions/0018-release-on-github-releases.md)）
- 環境に依る値（Vivado の場所・board files の場所）は Makefile に持ち、版が git の履歴に残るようにする
