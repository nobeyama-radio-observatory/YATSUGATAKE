# SAM45-Fine v1.0.0 — 性能評価

- 状態: **v1.0.0 の性能評価**（タグ `sam45-fine/v1.0.0`。配る .bit はタグの commit で作り直したもので、判定した .bit と FDRI が同じ。[`../../release.md`](../../release.md)）
- 測った期間: 2026-10-14〜10-21（YATSUGATAKE の移植の M3〜M6。経緯と生の数字は [`../../migration.md`](../../migration.md)）
- 判定の手順と合格の条件: [`../../../test/acceptance/sam45-fine/`](../../../test/acceptance/sam45-fine/)

**まとめ**: 21 判定はすべて通過。ただし P-8 の L-2 は 8 窓のうち D1 を「判定できない」とし（制限 1）、PS-3 の `db` は記録だけにした（制限 4）。
ch の応答は半 ch −3.00 dB・−3 dB 幅 1.000 ch（8 窓とも）、ch ごとの安定度は 5,120 s までラジオメータの式どおり、
8 時間・10.24 ms で 30 分の運転で取りこぼし 0。時刻は 1PPS の入口の LPF を含めて較正した（bound 5 ns）。

## 周波数応答

- **ch の形**（P-5、PFB T = 4・原型 sinc × Kaiser β 5）: 8 窓とも半 ch −2.998〜−3.001 dB、−3 dB 幅 0.9999 ch、隣の ch と −3 dB で交わる。隣の ch −41.5〜−53.1 dB（狭い窓ほど高い）、±1.5 ch より外のサイドローブ −41.7〜−56.8 dB
- **窓の平坦さ**（測り R、IF 3000 MHz の周りに 8 窓、±0.75 W・972 点）: 中央 90 % の p-p **0.021〜0.033 dB**（W 256 が最大）、−3 dB の端 ±0.487 W、窓の外の CW の折り返し最大 **−58.9〜−61.3 dB**
- **周波数の軸**（W-1）: CW の推定 IF と SG の差 −0.05・−0.01 ppm（外部 10 MHz で SG と共通）

## 強度

- **線形性**（P-8 L-1、10-21）: TP −18〜−28 dBFS で TP 4 本・8 窓ともパワーメーターに比例、残差最大 0.045 dB（D1）・ほかは ≦ 0.023 dB。比べの proj020 も同じ形（最大 0.047 dB）
- **単位の照合**（窓の和 / TP、中央 90 %）: proj020 と +0.012 %（10-17）・+0.013 %（10-21）
- **L-2**（窓 / TP のレベル依存）: 10-17 は 8 窓とも ≦ 0.0154 dB、10-21 は 7 窓 ≦ 0.0176 dB・D1 0.0489 dB
- **TP の dBm**: `tp_cal.json` の K（2026-10-06、ADC の口で測った値）を (2, 3) にも使う。根拠は 10-21 に同じ配線で dBFS − PM が proj020 と 0.03〜0.05 dB（≦ 0.07）。運転の STATUS に `tp_dbm` が出ることを確かめた

## 時刻

- 物差しは DSP のクロックの数 T（256 MHz、1 s = 256,000,000 ビート）。1PPS は原点と監視に使い、START_AT で 13 コアが同じ T に RUN（F-1）
- 束ねの区切り: 8 窓とも間隔 40,960,000 ns・e の幅 0 ns、窓の遅れの補正で e(窓 0) − e(窓 1) = −1.1 ns（PS-1）。束ねは PL の 40.96 ms と整数で一致（V2-a）
- **較正（形 (b)、2026-10-21）**: `pps_det_ns = 71.6`（1PPS の入口の LPF、LPF なしとありの M の差 71.4〜71.7 ns）・`adc_to_core_ns = 141.6・141.7・141.3・141.3`（ADC_A〜D）・`bound_ns = 5`。
  T-2 で測れるのは差 M = adc_to_core − pps_det だけなので、LPF（設置の性質）と bit の遅れを分けて持つ。LPF を外す・替えるときは pps_det_ns だけを測り直す
- **時刻の式の誤りを直した（PS、commit 9de1f3d）**: `timebase`・`s45acq` が pps_det_ns を引いていた（正しくは足す）。判定のときは pps_det_ns = 0 で結果に効いていない。直した PS で形 (b) と前の形が同じサンプルの時刻を出すことを `sw/pynq/test_cal_b.py` が見る（直す前は −143 ns で落ちた）
- 読み落とし: 40.96 ms × 703,125（8 時間）・10.24 ms × 175,767（30 分）で miss 0

## 既知の制限

1. **P-8 の L-2 の D1 は判定できない**（10-21）。D1（3840〜4096 MHz）は配線 N/S の BPF（〜3.9 GHz）の肩で、窓 / TP が 1.4 %。比べの proj020 も同じだけ外れた（0.047 dB）ので分光計の差ではないと見ている。10-17（前の配線・高いレベル）では 8 窓とも通過
2. **線形性の高い側（−10〜−18 dBFS）はこの bit・今の配線では測っていない**。同じ FDRI の移植元 proj021 2-5 の L-1（PATT 10〜20 dB、最大 0.012〜0.022 dB）で支える
3. **specd が止まっても共有メモリ `/dev/shm/psm_*` が残る**（溜まると次の specd が SIGBUS で止まる）。当面の運転の手順: specd を起こす前に `df -h /dev/shm` を見て、止まっている間に `psm_*` を消す
4. PS-3 の `db`（瞬断の深さ）は TP の区切りと瞬断の位相で決まるので記録だけ
5. 時刻: F-2 の 2 回の差 ≒ 0.8 ビートは、PPS のスタンプの 1 ビートの量子化（縁とクロックの位相）と見ている（未確認）。LPF なしの 1 回（10-21）は前の CAL（10-14）より 4.3〜6.1 ns 小さく、理由は分けられていない。bound_ns 5 はこれを含む
6. 800 MHz 帯の携帯電話の上りは、1PPS・10 MHz のケーブルから入る（IF 3251〜3281 MHz）。LPF を常設したが、効きはまだ判定できていない（電話の送信が揃わない。SG の方法で測り直す、study-rfsoc proj026）
7. 10.24 ms の運転は取得の CPU ≒ 75 %・loop_slow を数える（V2-b で 84,613 / 113,119 周、取りこぼしは 0）。40.96 ms（既定）では loop_slow 0
8. 8 時間の記録で ADC_C・D に同じ時刻の TP の小さな跳ね 2 回（±0.019 dB、区切り 1 個）。窓に直すと ≒ 0.0005 dB で判定に効かない。出どころは確かめていない
9. 窓の幅 8 MHz の FLAGS[4]（FFT IP に待たされた）は設計どおりの表示（判定に入れない）
10. `-1` の WNS +0.044 ns（余裕は小さい。RTL を変えたら閉じるかを確かめ直す）
11. **窓（DDC）の遅れ D(NS) は proj017（矩形の窓）の sim の値**（`timebase.WIN_DELAY_BEATS`、全 bit 共通）。PFB（T = 4）の入った RTL では sim で出し直していない。utc_ns の窓の項（D(NS) ＋ 1.5·L）のうち D(NS) の誤差は確かめていない（窓どうしの区切りは PS-1 で −1.1 ns まで揃っている）。次の版で sim を出し直し、(BIT_KIND, BIT_REV) の表に移す（[`../../spec/timing.md`](../../spec/timing.md) の「持ち越し」）
