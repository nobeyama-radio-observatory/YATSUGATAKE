# 2G-4 v1.0.0 — 性能評価

- 状態: **v1.0.0 の性能評価**（タグ `2g-4/v1.0.0`・リポジトリ全体 `v1.2.0`。判定したのは 64dbf45 の作り直しの .bit（FDRI は移植元・M3・M5 と同じ）。配る .bit はタグの commit で作り直し、FDRI が判定した .bit と同じことを確かめて配る。[`../../release.md`](../../release.md)）
- 測った期間: 2026-10-28〜10-30（YATSUGATAKE の 2G-4 の移植の M4〜M6。経緯と生の数字は [`../../migration-2g-4.md`](../../migration-2g-4.md) の「M5 の結果」「M6 の結果」）
- 判定の手順と合格の条件: [`../../../test/acceptance/2g-4/`](../../../test/acceptance/2g-4/README.md)

**まとめ**: 判定 11 のうち 10 が通過（F-2 は 2026-10-29 から 2G-4 では回さない。ADR 0023）。M6 の途中で 1 回、原因の分からないボードの固まりがあった（制限 1）。
30 分・2 時間の運転で取りこぼし 0、VCCINT 32.3〜33.0 A で平ら。TP の dBm はボードの較正ファイル（道 1）がそのまま当たる（同じ日の Wide と 0.01〜0.03 dB）。時刻の較正もボードの較正ファイル（`tcal board`）。

## 周波数応答

- **ch → IF**（H-2）: 4 点（3000.25・2500.5・3396.5・2597.25 MHz、後の 2 点は 2-for-1 の共役の側）× 4 窓とも、ピークの送る番号 i = 32767 − round((4096 − f) / df) で、軸と SG の差 0.0 Hz。ピークの前後 ±1 ch は −52〜−54 dB
- ch の形（半 ch・−3 dB 幅）は M6 では測っていない（模型との照合は sim の M-1・M-2、M2 で移植元と同じ出力）

## 強度

- **線形性**（M5 の 10-29 と M6 の 10-30）: TP −18〜−28 dBFS で TP 4 本・流れ 4 本ともパワーメーターに比例、残差最大 0.013 dB。流れ / TP のレベル依存 ≦ 0.0093 dB
- **TP の dBm**: ボードの `tp_cal.json`（道 1、Fine・Wide で測った K）がそのまま当たる。同じ日・同じ配線で dBFS − PM が 2G-4 A −0.82・B −0.79・C −0.78・D −0.67、Wide −0.85・−0.82・−0.79・−0.69 dB（差 +0.01〜+0.03、線 0.07）
- **束ねのレベル**（BUND）: tint 10.24・20.48・30.72 ms で 1 フレームあたりの電力が ±0.07 % の内

## 安定度

M6 では測っていない（2G-4 の判定の一覧にアラン分散が無い）。

## スプリアス

M6 では測っていない。

## 時刻

- 物差しは DSP のクロックの数 T（256 MHz）。ダンプ 10.24 ms（nacc 640 × 4,096 ビート）を束ねて tint（20.48 ms = 2 本、記録の nacc は 1,280）。4 窓の DUMP_T は同じ（H-0）
- **較正**: ボードの `time_cal.json`（形 (a)、M = A 69.6・B 71.2・C 69.7・D 69.7 ns、bound 5 ns）。2G-4 の F-2（PWR 3）の M との差は ±1.0 ns
- 30 分・2 時間の運転で miss 0・time_ok 1

## 既知の制限

1. **原因の分からないボードの固まりが 1 回**（2026-10-30 03:37 UTC、取得を START して ≒ 18 s）。ping も届かず電源の入れ直しで戻った。前の起動の journal に異常の記録なし。そのときの陽性対照の止まりは 2G の取得で空振りしていたので、リングの溢れではない。8 s 本当に止めても固まらない（直した後の V2-b の陽性対照）。30 分・2 時間の運転では起きていない
2. **リングのゆとりが予言より小さい**: 0.3 s の止まりでリングの山 48.3 MB（64 MiB の 72 %）。2G-4 は 102.4 MB/s なので、空のリングから PS が ≒ 0.65 s 止まると落ちる
3. ネットワークの tint の最小は 20.48 ms（予算 30 MB/s。10.24 ms は SET で断る。試験は `--net-budget-mbs 0`）
4. `-1` の WNS +0.047 ns（既定の戦略）。`hw/common/rec_fr.v` の版（`np − 1'b1`）では、どの戦略でも作り直しで閉じなかった（−0.23〜−0.35 ns）ので、2G-4 は rec_fr だけ `src/` の写し（移植元の版）を読む
5. ビルドの途中で Vivado が segfault することがある（2026-10-29〜30 に多い）。`impl_1` の中で落ちて dcp から回し直した回は、配置が一続きの回と別物になる
6. 安定度・スプリアス・ch の形は M6 では測っていない
