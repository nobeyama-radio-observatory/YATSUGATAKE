# 2G-2 v1.0.0 — 性能評価

- 状態: **v1.0.0 の性能評価**（タグ `2g-2/v1.0.0`・リポジトリ全体 `v1.4.0`。判定したのは M5 の .bit、commit b0dc6ea。FDRI は移植元・M3 と同じ。配る .bit はタグの commit で作り直し、FDRI が判定した .bit と同じことを確かめてから配る。[`../../release.md`](../../release.md)）
- 測った期間: 2026-10-31〜11-01（YATSUGATAKE の 2G-2 の移植の M4〜M6。経緯と生の数字は [`../../migration-2g-2.md`](../../migration-2g-2.md) の「M4 の結果」「M5 の結果」「M6 の結果」）
- 判定の手順と合格の条件: [`../../../test/acceptance/2g-2/`](../../../test/acceptance/2g-2/README.md)

**まとめ**: 判定 8 つがすべて通過。30 分・2 時間の運転で取りこぼし 0、VCCINT 19.5〜20.0 A で平ら（2G-4 の 6 割）。1 周の計 9.27 ms（tint 20.48 ms の 45 %）。直接の側と 2-for-1 の共役の側で利得が同じ（幅 0.01・0.02 dB）。2 コアに同じ ADC を入れると bit 単位で同じ。V2-b の陽性対照（リングを 8 s 読まない）でもボードは固まらなかった。時刻の較正はボードの較正ファイル（`tcal board`）。

## 測定系

## 周波数応答

- **ch → IF**（H-2）: 4 点（3000.25・2500.5 MHz が直接の側、3396.5・2597.25 MHz が 2-for-1 の共役の側）とも、2 窓でピークの送る番号が 30471・14479・43151・17575 で期待と一致、軸と SG の差 0.0 Hz。直接の側と共役の側で利得が同じ（ピーク / 中央値 − TP の幅 A0 0.01 dB・B0 0.02 dB。移植元 proj034 R-6 は A0 108.57〜108.68・B0 108.53〜108.57 dB）。A0 と B0 の差は 0.39 dB（R-6 では 0.04〜0.11 dB）。原因は確かめていない（判定は窓ごとの 4 点の幅で、窓どうしは比べない）
- ピークの前後 ±3 ch はピーク比 −52〜−53・−59〜−61・−64〜−66 dB（4 点・2 窓で同じ形）
- ch の形（半 ch・−3 dB 幅）は M6 では測っていない（模型との照合は sim、M2 で移植元と同じ出力）

## 強度

M6 では線形性・TP の dBm の照合を測っていない（2G-2 の判定の一覧に無い）。H-0 の TP は A −31.50・B −31.45 dBFS で移植元 proj034 R-2' と −0.1 dB。

## 安定度

M6 では測っていない。

## スプリアス

M6 では測っていない。

## 時刻

- 物差しは DSP のクロックの数 T（256 MHz）。ダンプ 10.24 ms（nacc 1,280 × 8,192）を束ねて tint（20.48 ms = 2 本）。2 窓の DUMP_T は同じ RUN_F0 から揃う（H-0・H-2）
- **較正**: ボードの `time_cal.json`（2G-2 は (10, 1) で、ADC → コアの道は共通。`rfdc_params.rpt` がほかの 4 本のビルドと同じ）
- 30 分・2 時間の運転で miss 0・time_ok 1

## 既知の制限

1. **`-1` の WNS +0.074 ns**（既定の戦略）。RTL を少し変えると負に戻る前提で扱う
2. ネットワークの tint の最小は 20.48 ms（予算 30 MB/s。10.24 ms は SET で断る。試験は `--net-budget-mbs 0`）
3. `s2_sep`・`s2_q`・`s2_chain` は 2G-4・2G-1-Fast の同じ名前のファイルと中身が違う。`s2_sep`・`s2_q` の一本化は 2G-2 の移植の後（別の PR）
4. `--fast` なしで tint 20.48 ms を回すと 1 周の p99 が 57 ms・loop_slow が数千になる（取りこぼしはリングが吸って 0）。`--prefault --fast --fast-ring` で起こす
5. 線形性・TP の dBm・安定度・スプリアス・ch の形は M6 では測っていない
